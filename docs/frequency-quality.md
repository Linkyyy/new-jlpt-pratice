# 词条例句、来源与纠错复核

词条详情的原题一览直接展示匹配片段，优先使用文章／听力原文，再用题干和选项。每道题最多 3 段，保留选项编号；完整预览、出处试卷筛选、分页和跳转原题继续可用。

高亮只使用词条、已确认别名及构建时实际出现的词形，不在服务器临时加载分词词典，不生成例句或翻译，不擅自判断当前语境的义项。过长原文以匹配位置为中心截取；无可靠匹配时明确提示展开核对，缺失资源不伪造原文。文本用 React 节点和偏移渲染，不注入题目 HTML。

## 本轮数据复核

扫描 14,825 个词条，记录 2,397 个多义／同音检查标记、412 个分词／释义检查标记、7,822 个分级检查标记。标记可能重叠，表示需要人工检查，不表示已证明错误。其中 7,142 条保留未分级，不按试卷等级或词频猜等级。

- 修正 6 条明确的词性专用释义：「いくら」副词／名词、「たま」副词、「いかん」副词、「かく」副词、「かなり」名词，避免同音鱼子、姓氏、灵魂等释义串入普通用法。
- 376 条假名词头存在多个有词典依据的汉字义项时，逐项展示，不再仅选第一个义项冒充唯一释义；每项可跳到词典出处。
- 「たまご」与「あたま」的完整连续词形修复了 6 处已观察到的错误拆分，仍要求原始分词边界完全覆盖，不跨选项／句子拼接。
- 名词「よく／欲」不再继承副词「よく」参考词表中的 N5 标记，保留未分级。
- 未改原题、答案及音频数据，来源题目仍为 8,759 道。没有恢复已经取消的“按唯一出现试卷等级暂定分级”。

词条详情可展开“释义与分级来源”：展示释义出处、公开词表／补充核对／站内估级、来源版本与许可。分级仍是非官方参考。每个已有等级都有对应来源记录；多义、缺失依据、多等级或估级需要在具体语境中进一步核对。

## 管理与反馈闭环

管理员入口 `/feedback`，展开 **词条质量复核**，可按多义词、可疑分词、分级待核对筛选、搜索、分页，点击词条直接打开详情。沿用 `FEEDBACK_ADMIN_USERS` 与云备份管理员账号权限；普通用户不能读取复核 API 或反馈管理列表。

1. 用户在词条详情提交纠错，服务端核对当前词条与索引版本，保存不可随意伪造的词条快照。
2. 服务端返回独立的私密回执，D1 只存回执 SHA-256 摘要。浏览器最多保留 100 份回执；不保存反馈正文或账号密码。回执当前仅保存在当前浏览器，不包含在学习云备份中，清除浏览器数据后无法恢复。
3. 管理员核对原题与词典／分级来源，状态可为待处理、处理中、已处理。词条反馈在标记已处理前必须填写至少 5 字说明，并自动记录当前部署的词库版本。说明可以记录实际修正，也可以说明保留原因或证据不足。
4. 用户再次打开同一词条的“词条纠错 → 我的反馈”，手动点击“查看处理进度”，查看状态、处理说明和核对版本。仅持有该回执可查询，不提供公开反馈列表，也不在查询结果返回原始正文或回执摘要。
5. 词库修改仍通过审核后的代码／数据提交、`npm run build` 重建和部署发布，不把用户反馈自动写入词库。管理员标记已处理本身不等于修订已经发布。

沿用现有 `question_feedback` 表的 JSON 快照存储回执摘要、处理说明与版本，**不需要执行新 SQL**。旧题目反馈、旧词条反馈继续可管理；此前没有生成回执的历史反馈无法通过回执查询。

## 请求与费用

复核列表仅在管理员展开时加载，受管理员认证与每实例每 IP 30 次／分钟限制。反馈回执只在用户点击查询时读取 D1，每次 1 个按 ID 查询；没有轮询、自动同步或新增数据库计数写入。查询受同源、请求体、统计访问校验与每实例每 IP 30 次／分钟限制。原有反馈提交和管理限流保留。

## 验证

`scripts/test-frequency-evidence.mjs` 覆盖原文定位、偏移、选项编号、多义项、来源对齐及分级保守规则；`scripts/test-question-feedback.mjs` 用 SQLite 执行实际 SQL，验证回执、状态流转、处理说明与权限隔离。词频、PDF／Excel、收藏复习与安全相关回归一并运行。浏览器测试分别验证桌面和移动端，云端传输使用模拟数据，没有提交线上测试反馈。
