# 白屏与连接问题排查

`/connection-check.html` 是独立的静态检测页，样式和检测脚本均内置，不依赖 React 或应用脚本。它不会请求账号接口、读取学习数据或自动上传结果。

## 在故障设备上检测

1. 打开 `https://new-jlpt-pratice.vercel.app/connection-check.html`。
2. 如果直连打不开，先开启代理打开检测页，然后保留页面、关闭代理。
3. 点击“重新检测”，等待检测结束，再点击“复制检测结果”发给维护者。

检测页依次请求静态连接探针、首页以及首页 HTML 引用的同源脚本和样式（最多 20 个，最多两个请求并发）。每个请求等待最多 8 秒，重新检测会要求服务器验证缓存，避免只读取浏览器已有资源。

## 结果能说明什么

- HTTP 403 / 429：请求被拒绝或限速，需要结合 Vercel 和应用防护日志排查。
- 返回安全验证页：检查平台防护及故障设备的出口 IP；检测不绕过验证。
- 首页通过但脚本或样式失败：优先检查对应静态资源的连接和返回类型。
- 请求失败或超时：浏览器无法直接区分 DNS、TLS、路由和拦截，需要结合故障网络继续检查。
- 全部请求通过：只说明本次请求成功，不保证应用脚本执行正常。

同一台 Safari 开代理后可用，说明问题与网络路径或出口环境有关，但不能仅凭这一点断定 DNS、IPv6 或某项平台规则有问题。开发环境的连接结果也不能代表中国大陆故障设备的连接结果。

## 应用加载失败时

首页内联启动检测独立于应用脚本运行。应用尚未初始化且出现脚本错误、资源错误或超过 15 秒时，展示重新打开和连接检测入口；React 错误边界另提供重试和返回首页。关闭 JavaScript 时提供可见提示。

当前标签页的 sessionStorage 只保留最近一次启动时间、简短状态码及最多 8 个同源静态资源路径，不保留查询参数、异常堆栈或用户学习数据。检测结果还包含用户主动分享的浏览器版本、语言、时区和请求状态。

## 验证

单元测试：`node --test scripts/test-startup-check.mjs`。此外验证生产构建、代码检查和浏览器中正常加载、脚本请求失败、关闭 JavaScript、403 / 429、安全验证页以及错误边界重试。开发环境使用 Chromium 模拟故障，不替代故障设备上的真实 Safari 检测。
