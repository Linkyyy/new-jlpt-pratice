# 请求限流与资源防刷

新增的全站实例内突发限制、统计接口访问校验及 Vercel／R2 上线操作，见 [网站安全防护与上线设置](./security.md)。这些代码计数不新增 D1 读写。

## 已经由代码保护的请求

站内 API 在读取题库文件、查询 D1 或计算密码之前，先经过轻量的内存突发限制。超出后返回 HTTP `429`、中文错误提示及 `Retry-After` 秒数，响应不缓存。拒绝的突发请求不写 D1。

| 接口 | 同一 IP 的实例内限制 | 其他限制 |
| --- | --- | --- |
| 收藏题目详情、收藏练习题目数据 | 合计 120 次／分钟 | 每次最多 100 个 ID；实际请求体最多 30,000 字节 |
| 云备份账号状态 | 120 次／分钟 | 每个会话 60 次／分钟 |
| 云备份注册、登录、退出 | 30 次／分钟 | 原有 D1 持久限制保留：IP 30 次／15 分钟，账号 15 次／15 分钟，注册 IP 5 次／小时 |
| 从云端导入 | 60 次／分钟 | 每个会话 30 次／分钟 |
| 备份到云端 | 60 次／分钟 | 每个会话 20 次／分钟；原有账号 D1 持久限制 20 次／分钟保留 |
| 清空云端学习记录 | 30 次／分钟 | 每个会话 20 次／分钟；原有账号 D1 持久限制 20 次／分钟保留 |
| 暗号校验（启用时） | 20 次／分钟 | 实际请求体最多 1,000 字节 |
| 统计查询 | 60 次／分钟、1,200 次／小时 | 必须先通过统计暗号验证；禁止共享缓存 |
| PDF／Excel 导出 | 6 次／分钟、20 次／小时 | 必须先验证；每实例同时最多 1 个导出任务 |
| 词条反馈回执查询 | 30 次／分钟 | 仅持有对应私密回执可查询；每次 1 个按 ID 的 D1 读取，不轮询 |
| 管理员词条质量复核 | 30 次／分钟 | 先校验管理员身份；题库复核数据从构建索引读取 |

反馈接口也复用同一限流工具；其具体提交与管理额度见反馈功能文档。

请求体大小检查读取实际字节流，不依赖可缺失或伪造的 `Content-Length`。达到上限时取消继续读取。内存计数器按散列键保存且有容量上限，避免攻击者不断更换标识导致内存无限增长；不记录原始 IP。

D1 持久计数使用带条件的原子 UPSERT：已满额的计数行不会继续更新。已知满额窗口在当前实例缓存，后续拒绝不再访问 D1；清理过期限流行改为定期执行，不再每次请求都做清理。不同实例首次发现同一个已满额度可能仍有一次数据库查询，但不会修改满额行。

## IP 可信边界

部署到 Vercel 时，仅使用平台重写的 `x-vercel-forwarded-for`，忽略用户自行提交的 `x-forwarded-for`。自行部署时默认使用共享的 `unknown` 桶，避免信任未经验证的代理头。

如果自建的反向代理会**覆盖**外部客户端提供的 `x-forwarded-for`，可在服务端设置：

```dotenv
TRUST_PROXY_IP_HEADERS=true
```

没有可信代理时不要启用。没有识别到可信 IP 的客户端会共用一个桶。

## 代码限制的范围

内存限制只属于当前 Node 实例，Vercel 多实例、冷启动和跨区域不会共用计数。因此它用于降低突发查询与计算消耗，**不能作为整个站点的全局流量或费用硬上限**。现有 D1 的账号／IP 持久限制仍跨实例生效；为了避免每次题库读取都产生 D1 写入，题库数据读取没有再新增数据库计数。

网页、Next 静态文件、题库资源下载和所有地区的全站请求，需要使用 Vercel Firewall／平台 DDoS 防护与费用告警限制。代码返回 429 的请求仍然会到达托管平台，不能保证零函数调用或零传输费用。可在 Vercel 项目的 Firewall 中为 `/api/*` 添加 IP 速率规则，先记录观察正常请求量，再启用限流；具体功能、额度和价格以当前账号套餐为准。

## R2 的公开 MP3／JPG 无法由网站代码拦截

播放器与图片直接请求 `*.r2.dev`，不经过本站 API。用户也能复制公开 URL 请求。因此，本站新增的 API 限流**不会限制 R2 直连音频、图片**，前端禁用按钮、CORS 和隐藏 URL 都不能阻止直接请求。

需要在 Cloudflare 侧开启资源防护，不能仅靠本仓库代码完成：

1. 在 Cloudflare 管理的域名下创建 R2 自定义域名，例如 `media.example.com`，并在 Bucket 的自定义域名设置中关联它。
2. 将 Vercel 的 `NEXT_PUBLIC_AUDIO_BASE_URL` 改为该 HTTPS 域名并重新部署。图片使用相同基础域名；保持现有 `audio/...`、`pic/...` 对象路径不变。
3. 在该域名的 Security／WAF 中为资源路径设置按 IP 的 Rate Limiting 规则。先观察请求量；音频拖动会发出多次 `Range` 请求，移动网络也可能有多人共用 IP，不能把正常播放误判为攻击。规则可匹配媒体域名下的 GET／HEAD 请求和 `/audio/`、`/pic/` 路径，拦截时选返回 429，避免挑战页面破坏播放器。可用规则数、匹配字段与计数窗口取决于套餐。
4. 测试播放、拖动、倍速、图片放大均正常后，关闭 Bucket 的 `r2.dev` 公共开发 URL，避免绕过自定义域名规则直接下载。
5. 配置使用量告警，定期查看 R2 操作数、WAF 拦截和 Vercel 使用量。WAF 按 IP 也不能阻止大规模分布式来源，阈值不是绝对费用保证。

若需要按登录账号控制资源，或者设全局每日资源请求上限：将 Bucket 改为私有，通过 Cloudflare Worker 的 R2 Binding 提供资源；由 Worker 验证短期访问凭证，结合 Durable Objects／适当持久存储做全局计数，保留音频 `Range` 和缓存响应。此方案可继续避免 Vercel 中转 MP3，但需要单独部署 Worker、配置权限并计算 Workers 成本，目前没有替用户更改生产配置。

参考：[R2 公共 Bucket 与自定义域名](https://developers.cloudflare.com/r2/buckets/public-buckets/)、[Cloudflare Rate Limiting](https://developers.cloudflare.com/waf/rate-limiting-rules/)、[Vercel Firewall](https://vercel.com/docs/vercel-firewall)。
